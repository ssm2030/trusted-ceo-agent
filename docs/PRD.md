# Trusted CEO Agent PRD

- 상태: Working Draft v0.1
- 기준일: 2026-07-17
- 문서 역할: 본선용 제품 요구사항의 정본
- 변경 원칙: 확정된 결정만 본문에 반영하고, 미확정 사항은 마지막 절에서 관리한다.

## 0. 문제 정의와 제품 정의

### 문제

CEO는 재무·고객·상품·운영·인력·리스크 데이터가 여러 파일과 부서에 흩어져 있어, 자신이 아직 인지하지 못한 중요한 경영 문제를 빠르게 발견하고 원인과 대응 방향까지 통합 판단하기 어렵다. 기존 방식은 경영기획, FP&A, 데이터 분석가, 운영 담당자, 컨설팅팀과 전문직의 순차 검토를 요구해 시간이 오래 걸리고 판단 근거도 분산된다.

### 제품 정의

Trusted CEO Agent는 제공된 기업 데이터와 확인된 사업 맥락을 바탕으로 재무성과·수익모델·고객·상품·운영·인력·조직·리스크·통제 전반을 CEO 관점에서 점검하여, 경영진이 인지하지 못한 중요한 이상 신호를 발견하고 근거 기반 문제 정의·원인 가설·검증 계획·우선순위·조건부 해결책을 제안하는 경영진단 및 의사결정 보좌 에이전트다.

### 한 줄 설명

기업 데이터를 근거로 CEO가 놓친 경영 문제를 발견하고, 원인 검증과 조건부 해결책까지 제안하는 AI 경영 트러블슈팅 에이전트.

### 대체·보좌 경계

- CEO를 대체하지 않는다.
- 경영기획·FP&A·데이터 분석가·컨설팅팀이 수행하던 1차 진단, 문제 구조화, 의사결정 자료 준비를 자동화한다.
- 중요성·전략적 절충·전문 판단·최종 실행 책임은 사람에게 남긴다.

## 1. 사용자와 전문 범위

### 주요 사용자

- 고객사 CEO 및 경영진
- CEO의 의사결정을 지원하는 경영기획·FP&A·운영 책임자

### 보조 사용자

- PwC 컨설턴트 및 회계·세무·법무·노무 전문가
- 고객사 데이터·업무 담당자

### 분석 관점

- 재무·관리회계: 매출, 비용, 수익성, 현금흐름, 운전자본, 단위경제성
- 사업·전략: 수익모델, 고객·상품 포트폴리오, 집중도, 성장 구조
- 운영: 생산성, 가동률, 병목, 낭비, 품질, 프로젝트 수행
- 인력·조직: 인력 활용, 비용 구조, 역량, 이직·조직 운영 신호
- 리스크·통제: 데이터 불일치, 내부통제 취약 신호, 계약·규제 검토 필요성

### 전문직 경계

- 회계·세무·법무·노무 관점의 데이터 분석과 이슈 발견은 수행한다.
- 정확한 회계처리, 세액, 위법 여부, 감사의견 등 자격과 책임이 필요한 최종 결론은 내리지 않는다.
- 전문 판단이 필요한 경우 문제, 근거, 불확실성, 필요한 문서, 정확한 검토 질문을 전문가 패킷으로 만든다.

## 2. 입력 계약

입력은 회사 데이터만이 아니라 다음 세 묶음으로 구성한다.

### Mission Contract

- CEO의 결정 질문
- 현재 증상 또는 우려
- CEO가 생각하는 원인 가설
- 중요 의사결정과 시간 범위
- 우선순위와 제약 조건
- 최근 사업·조직·정책 변화
- 분석 포함·제외 범위

고객 요청이 없으면 기본 미션은 `제공된 데이터에서 CEO가 인지하지 못한 중요한 경영 문제를 탐색한다`이다. 고객의 원인 설명은 사실이 아니라 우선 검증할 가설로 취급하며, 최소 하나의 반대 관점을 함께 확인한다.

### 회사 데이터

- 정형 데이터: CSV, XLSX, JSON 등
- 선택형 비정형 자료: 계약, 정책, 인터뷰, 보고서
- 기간·단위·통화·집계 기준과 원본 출처

### 선택형 외부 근거

- 회사가 제공한 공식 자료
- 공신력 있는 공식 외부 자료
- 외부 자료는 근거 보강용이며 경쟁사 비교를 기본 목적으로 삼지 않는다.

## 3. 네 가지 사고 구조

### 1층: Evidence Core

원본 보존, 파일·열 의미 추정, 품질 검사, 표준화, 재현 가능한 계산, 출처 추적, 분석 가능 범위와 사각지대 생성을 담당한다. 산업 지식 없이 관찰 가능한 사실과 신호까지 만든다.

### 2층: Pack Stack

- Mission Pack: CEO 요청 처리 원칙, 산출물, 판단 경계
- Domain Pack: 산업·사업모델 용어, KPI, 기대 관계, 원인 메커니즘, 금지 해석, 전문가 트리거
- Problem Pack: 발견된 문제를 검증할 분석 부품, 지지·기각 조건, 필요 데이터, 조건부 대응 유형

Mission은 본선 동안 거의 고정하고 Domain과 Problem을 입력에 맞게 선택한다. 검증되지 않은 팩은 `provisional`로 표시하고 결론 강도를 제한한다.

### 3층: Bounded AI Reasoning

AI는 다음 순서로만 추론한다.

`관찰 사실 → 경영적 의미 → 문제 후보 → 원인 가설 → 반대 가설 → 구별할 검증 → 현재 근거 수준 → 추가 데이터·질문 → 조건부 대응안`

AI는 관점별 진단 카드를 만들 수 있지만 전사 최종 원인·중요도·해결책을 개별 관점에서 확정하지 않는다.

### 4층: Human Decision

- 데이터 의미와 사업 맥락 확인
- 의도된 전략과 실제 이상 구분
- 문제 중요도·분석 범위·우선순위 승인
- AI 가설 반박·보완
- 전문가 검토와 최종 고객 전달·실행 승인

### 공통 Trust Kernel

Trust Kernel은 네 층 전체에 다음을 강제한다.

- 원본 데이터 불변
- 계산 사실과 AI 해석 분리
- 모든 중요 주장에 출처·계산식 연결
- 고객 주장을 가설로 처리
- 반대 증거·기각 조건·판단 불가 표시
- 승인 전 단계 진행 금지
- 전문직 최종 결론 제한
- 상태·팩·승인·출력 버전 기록
- 최종 Evidence Validator 실행

## 4. 작업 단계

1. Context Gate: CEO 질문, 사업모델, 기간, 회계·운영 정의와 제약 확인
2. Data Intake: 원본 목록, 스키마·단위 추정, 품질 경고, 표준 스키마 매핑
3. Data Capability Map: 현재 데이터로 검토 가능한 관점과 사각지대 결정
4. Parallel Evidence Scan: 적용 가능한 모든 저비용 결정적 계산을 병렬 실행
5. Parallel Lens Assessment: 필요한 관점이 동일한 Fact Register와 Pack Stack을 사용해 구조화된 진단 카드 생성
6. Join Barrier: 모든 병렬 작업 완료 후 중복·공통 원인 후보를 코드로 사전 정리
7. Integrated Reasoning: 단일 종합 AI가 관점 간 충돌, 인과관계, 중요성, 긴급성, 추가 검증 필요성을 통합
8. HITL Gate: 사람이 데이터 의미, 문제 후보, 우선순위, 심화 분석 범위를 승인·수정
9. Focused Deep Dive: 승인된 문제에 필요한 계산과 검증을 실행하고 가설·반대 가설·조건부 대응안을 갱신
10. Expert Routing: 회계·세무·법무·노무 전문 검토가 필요한 이슈의 전달 패킷 생성
11. Trusted Output: CEO 브리프, 이슈 트리, 근거 카드, 모니터링·사각지대, 전문가 패킷 생성
12. Final Validation: 근거·계산·승인·등급·출력 정합성 검증

## 5. 코드·AI·사람의 역할

| 단계 | 코드 | AI | 사람 |
|---|---|---|---|
| 데이터 접수 | 파일·스키마·단위·품질 검사 | 모호한 의미의 매핑 제안 | 중요한 매핑 확인 |
| 범용 검진 | 결정적 계산과 신호 생성 | 신호의 경영적 의미 설명 | 사업 맥락 제공 |
| 관점별 분석 | Fact·Pack·출력 계약 제공 | 문제·원인·반대 가설 후보 생성 | 필요 시 가설 보완 |
| 전사 종합 | 중복·근거·상한 검증 | 관점 연결, 충돌 비교, 문제 구조화 | 중요도·범위 승인 |
| 심화 분석 | 승인된 계산 실행 | 검증 결과 해석, 조건부 대응 작성 | 우선순위·대응 승인 |
| 전문 이슈 | 트리거와 패킷 검증 | 검토 질문과 자료 목록 작성 | 전문가가 최종 판단 |
| 최종 결과 | 근거·승인·정합성 검증 | CEO 언어로 설명 | 최종 전달·실행 승인 |

## 6. 결과물의 틀과 성격

### CEO 1페이지 브리프

- 지금 확인된 핵심 상황
- 왜 중요한가
- CEO가 결정하거나 즉시 확인할 사항
- 조건부 대응 방향
- 주요 불확실성과 사각지대

### 이슈 트리

관찰 사실, 문제, 원인·반대 가설, 검증, 대응의 연결 구조를 보여준다.

### 근거 카드

관점, 관찰 사실, 경영 영향, 문제 후보, 원인·반대 증거, 필요한 확인, 근거 ID를 표준 형식으로 제공한다.

### 결과 등급

등급 명칭과 공통 판정 원칙은 Trust Kernel/Mission Pack에 고정하고, 산업별 중요성 기준과 전문가 트리거는 Domain Pack이 제공한다. 이번 고객의 우선순위는 Mission Contract와 HITL로 반영한다.

- Decision Required: 근거가 충분하고 CEO 결정이 필요한 문제
- Immediate Verification: 영향이 크거나 긴급하지만 추가 검증이 필요한 문제
- Expert Review Required: 전문직 검토가 필요한 문제
- Monitor: 현재 영향·긴급성이 낮아 추적할 사항
- Appendix Signal: 단발성·중복·낮은 중요도의 신호
- Not Assessable: 데이터 부족으로 판단할 수 없는 영역

본문은 고정 개수로 자르지 않고 첫 세 등급에 해당하는 문제를 모두 포함한다. 문제가 많으면 동일 원인을 이슈 트리로 묶는다.

### 전문가 검토 패킷

이슈, 사실·출처, 현재 가설·반대 가설, 판단하지 않은 사항, 필요한 문서, 전문가에게 묻는 정확한 질문, 영향도·긴급도를 제공한다.

### 감사 패키지

계산식, 원본 연결, AI 판단, 팩·버전, HITL 수정·승인, 최종 검증 결과를 보존한다.

## 7. 속도 설계

- 원본 정규화와 Fact Register를 한 번만 생성해 모든 관점이 재사용한다.
- 적용 가능한 모든 결정적 계산은 독립 함수로 병렬 실행한다.
- 관점별 AI는 긴 보고서가 아니라 제한된 진단 카드만 반환한다.
- 다른 관점 결과 없이 완결되는 일만 병렬화한다.
- 원인 비교, 중요도, 해결책 충돌, 결과 등급, CEO 서술은 Join Barrier 이후 단일 종합 단계에서 처리한다.
- 관점이 많으면 재무·사업, 운영·인력, 리스크·통제 단위로 계층 종합한다.
- 플러그인과 향후 웹은 동일한 중간 JSON과 최종 산출물을 사용한다.
- 데모는 저장된 실행본을 기본으로 사용하고 핵심 HITL 또는 질의 한 단계만 실시간 실행한다.

## 8. 검증과 POC 합격 기준

### 자동 검증

- 단위 테스트: 파싱, 정규화, 단위 변환, 계산식
- 계약 테스트: 출력 스키마, 근거 연결, 승인·상한·전문직 경계
- 통합 테스트: 처음부터 최종 패키지까지 상태 전이
- 순차·병렬 동등성: 코드 결과는 정확히 동일해야 함
- 반복 안정성: 동일 입력 10회에서 Fact·출처·분석 가능성·핵심 라우팅이 유지되어야 함
- 변형 테스트: 열 이름·순서·단위·파일 분할·무관 열 추가에도 핵심 결과 유지
- 안전 중단 테스트: 정상·데이터 부족·충돌·미지원 도메인에서 과도한 결론 금지

### 사람 평가

- 문제 정의가 경영적으로 타당한가
- 중요한 반대 가설을 놓치지 않았는가
- 해결 방향이 실제 의사결정에 사용 가능한가
- CEO가 문제, 근거, 결정, 불확실성을 빠르게 이해할 수 있는가
- 전문가 패킷이 바로 검토 가능한 수준인가

### 절대 실패 조건

- 출처 없는 계산 또는 중요 주장
- 승인되지 않은 심화 분석·대응안
- 고객 주장을 사실로 취급
- 데이터 부족 상태에서 확정 해결책 제시
- 회계·세무·법무·노무 최종 전문 결론
- CEO 결과와 근거·승인 기록 불일치

## 9. 범위와 우선순위

1. 플러그인 상세 설계·구현
2. POC 데이터 변형·검증·반복 테스트
3. 대회 당일 Pack 수정 절차와 프롬프트
4. 시간이 허용되면 웹 시연 인터페이스와 부가 기능

웹은 별도 분석 엔진을 만들지 않고 플러그인의 동일 결과 JSON을 조회·검토·질의하는 얇은 인터페이스로 시작한다.

## 10. 비목표

- CEO의 최종 의사결정과 책임 대체
- 모든 산업과 모든 기업 문제의 완전한 탐지 보장
- 근거 없는 완성형 컨설팅 해결책
- 감사·회계·세무·법률·노무 공식 의견 자동화
- 경쟁사 비교 중심 제품
- 본선 1차 구현에서 음성, RAG, 이메일 자동 발송, 외부 시스템 실연동 필수화

## 11. 미확정 사항

- 공통 Reasoning Contract의 정확한 필드·상한·실패 처리

- HITL 승인 지점과 수정 가능한 필드
- POC 대표 시나리오, 숨겨진 정답, 합격 임계값
- 모델·서브에이전트 구성과 실행 시간 예산
